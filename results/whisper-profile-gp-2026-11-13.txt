## Per encoder window (5.37 s) [EST: GPU sums split by launch counts; prompt GEMMs are a small part]
GEMM ~2.8 s + activation packing + epilogue ~0.57 s + attention ~1.09 s = ~4.5 s on the GPU; ~0.9 s (16 %) is CPU work
and waits: LayerNorm, GELU, bias adds, conv1d (im2col and its MUL_MAT, declined because src1 is F16), sync.
For comparison, OpenVINO on the same window (PERF_COUNT): FullyConnected with fused epilogue ~4.5 s, SDPA 1.6 s,
convolution 0.7 s -> our GEMM (~3.4 s incl. packing) and attention (1.1 s) are both faster.
## Reading
- Encoder 69 %: the GPU part is ~84 % of each window; the rest (~0.9 s/window = ~29 s per run, 11 % of the run) is CPU
  ops + conv + waits. Packing + epilogue (18.9 s, 7 % of the run) is larger than in llama (M 1500, many GEMMs).
- Decoder 26 %: CPU only (M = 1), 23.6 ms per token. Unlike quantized LLMs, whisper's weights are F16, so the CPU
  reads the same 2 B per weight as the GPU would. [EST] decoder weights ~170 M params x 2 B = ~340 MB per token ->
  CPU ~14 GB/s; GPU GEMV at ~27 GB/s (docs/ggml-backend-design.md) would take ~12 ms + ~33 waits x ~0.19 ms = ~18 ms:
  ~1.3x on the decoder, ~6 % of the run. To be measured before any work (the decoder parameter count is an estimate).
