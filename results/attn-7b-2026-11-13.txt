=====================================================================================

Code: ggml-backend branch at 3b3e68c + this change. (attention).

## 1. Model of the two designs (written 2026-11-13 20:52 CET, before building anything)

Problem: at D 128 a subgroup holds RQ 2 query rows (FP32 Q and O, 64 GRF). Rows are token-major (row = t*G + hh), so
with G 7 the pair (row0, row0+1) spans tokens t and t+1 whenever row0 % 7 == 6: one subgroup in 7. asm/attn.cl takes
one visible-key count per subgroup from row0's token, which is one key short for row 1 under a causal mask (dvis 1).
Also n_q*7 is odd for odd n_q (last ubatch of a prompt), which the host now refuses (n_q*G % RQ).

(a) pad G to 8: a virtual 8th query head per KV head (Q of head 6 reloaded or zero, O not stored).
    Work: 8/7 of the useful rows, every block, all depths: +14.3 % kernel time. The hot loop is the stock Qwen loop
    (sched4 RQ 2 NK 2), so its rate is the Qwen 1.5B kernel's: ~306 GFLOPS executed (HD 530, section 12) / ~315
    (UHD 620, kcl) -> useful 268 / 276 GFLOPS. Needs a template change (row -> (t, hh) with G' 8, store skipped or
    redirected for hh 7) but no generator change. Odd n_q: no problem (n_q*8 even).
(b) per-row visibility: each row r gets its own limit lim_r = min(nk, vis0 + dvis*t_r); the loop runs to the larger
    (row 1's) limit; only the last key block masks, per row (lim_0 >= lim_1 - 1 lies in the same last block, or at its
    first key = row 0 fully masked there: max -1e30 < m, p = 0). Extra cost: RQ*NK = 4 instead of 2 compare
    instructions in the one masked block per row pair, 2 scalar movs before the loop; 1/7 of the subgroups (the
    spanning ones) run one extra block when lim_0 is a multiple of 16 (1/16 of those): ~0.06 % more blocks.
    Full blocks: unchanged. Predicted rate = the Qwen 1.5B kernel's on visible keys: ~305 (HD 530) / ~312 (UHD 620)
    GFLOPS, i.e. (b) ~13-14 % faster than (a). Odd n_q: clamp row indices to n_q*G - 1 in the template (the last
    subgroup computes the same row twice and stores identical values to the same address).
    Generator change: per-row limits must reach the generated mask. The generator only knows its internal row
    numbering (S chains); to tie a limit to an internal row by data flow, the template initialises IGC's l##r to
    (float) lim_r (the generator zeroes its l registers before the loop anyway), and attn_gen.py reads lim_r from the
    l register whose accumulating add takes that row's exp'd scores.
Decision rule: (b) if its measured kernel rate is >= 5 % above (a)'s (proxy for (a): the stock template built for
G 8, H 32, H_kv 4, whose hot loop is the same as (a)'s; only prologue/epilogue differ) and every correctness test
passes; otherwise (a).
