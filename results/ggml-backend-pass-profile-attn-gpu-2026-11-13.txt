GPU idle                         ~225 ms    9.6 %
## The idle time is submission, not CPU ops (KCL_PHASES=1)
execbuf ioctl: 1298 calls (221 per pass + 193 first-use dequant), 0.74-0.83 ms wall each, all of it CPU time in the
kernel (softpin + NO_RELOC already; ~9-10 objects per execbuf). 221 x 0.74-0.83 = 165-185 ms per pass = 7-8 %.
With GEN9BLAS_NO_USERPTR=1 (copies instead of userptr): execbuf still 0.67 ms, pp512 193.5 -> userptr pinning is
not the cause. GEM_WAIT: CPU 28-48 us per call (sleeping wait, fine).
Left for CPU ops (norms, RoPE, adds, get_rows) and the rest: ~40-60 ms per pass (~2 %).
## Reading
- GEMM is 80 % of the pass and issue-bound (~10 % headroom inside the kernel = ~8 % of the pass).
- The largest item outside the GEMM is the execbuf ioctl: ~0.75 ms of kernel CPU per submission while the GPU waits.
  Unknown why it costs that much for ~9 softpinned objects [open: i915 per-object work, batch size, or fences].
  Levers: find the cost (e.g. ftrace/perf on i915_gem_do_execbuffer needs root), or submit the next independent op
  before waiting (Q/K/V GEMMs share an input) so the ioctl overlaps GPU work.
- Activation packing + epilogue 7 %; attention 3 %; CPU ops ~2 %.
- No single new kernel has more than ~8 % of the pass to gain.
