## 1. A/B faster mask analysis (ABBA)
  head  488 / 489 tok/s   mask analysis 3.04 / 2.99 s per server run
  new   516 / 516 tok/s   mask analysis 0.31 / 0.31 s
  -> +5.6 % end to end, analysis 9.7x faster in the server (synthetic 4.7x); same runs and launches (3052 runs,
  3304 launches), so the GPU work and the embeddings are identical. CPU unit test: 20000 random masks, 0 mismatches;
  test_attn on tc: 7 mask modes NMSE <= 9e-14 (results/attn-qwen3-short-tc-2026-11-14.txt).

## 2. Where the time goes (GEN9_PROF=1, 499 tok/s: the per-op waits slow it down)
  graph_compute 57.3 s
  FFN fused (gate+up+SwiGLU+down)  42.6 %   626 GFLOPS
  MUL_MAT (O projection etc.)      20.6 %   571 GFLOPS
  Q/K/V group                      10.8 %   554 GFLOPS
  FLASH_ATTN                       17.2 %   (9.3 s in a normal run, 199 GFLOPS incl. pinning/submit/wait)
  RMS_NORM(+MUL) 5.0 %, ROPE 2.0 %, ADD 1.6 %  <- overstated: each carries a wait a normal run does not have
  -> GEMMs are 74 % of the time at 554-626 GFLOPS (~70-78 % of the FP16 peak at the run's clock) [MEAS / EST peak];
  attention 17-18 %; elementwise ops below ~5 % in a normal run.

## 3. kcl phases (KCL_PHASES=1, 514 tok/s)
  EnqueueNDRange 47574 x 2.2 us; execbuf 11678 x 165 us CPU (1.9 s, includes userptr pinning); GEM_WAIT 11678 x
  4.46 ms (= GPU time); 9.3 objects per execbuf.
  KCL_USERPTR_MB=2048: 521 tok/s (+1 %), attention 9.30 -> 8.93 s -> the varying pinned ranges of the general-mask
  path (fable review) cost ~0.4 s here, not more [MEAS].

## 4. -ub sweep (new)
  -ub 512  516 tok/s;  -ub 1024  488 tok/s;  -ub 2048  476 tok/s  -> keep 512 (bigger ubatches are slower here;
  attention time unchanged at ~9.3 s, mask analysis grows to 1.0 / 1.4 s).
  (prof.out prints "mask analysis 2.990 s" after these two runs: a script bug, it grepped the head log.)

## Consequences for the plan
- Faster mask analysis: done (+5.6 %).
- Stable pinning ranges: worth <= ~1 % -> low priority. One kcl operation per node / array kernel: attention
  overhead beyond the kernel is now small (199 GFLOPS vs ~225 synthetic at this length) -> not worth days.
- The remaining lever is GEMM (74 %), already at ~70-78 % of peak; the last-layer-only-for-last-token trick
  (llama.cpp patch, ~3 % est.) cuts GEMM work instead of speeding it up.
